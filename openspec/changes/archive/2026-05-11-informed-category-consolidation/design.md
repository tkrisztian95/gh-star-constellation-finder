## Context

`consolidateCategories` currently runs two AI passes:
1. **Pass 1** — language/qualifier deduplication (e.g. "Rust CLI Tools" + "Go CLI Tools" → "CLI Tools")
2. **Pass 2** — budget-aware consolidation against the name list + existing lists

Both passes operate solely on category name strings. The AI has no signal about how many repos belong to each category or what topics those repos carry. As a result, it can legally merge "Rust CLI Tools" (2 repos) with "CLI Tools" (35 repos) or leave "Web Scraping" (1 repo) separate when it should fold into "Data Pipelines" (20 repos).

The fix is to inject a compact distribution summary — repo counts and representative topics per proposed category — into the consolidation prompt. This is generated by a lightweight new AI pass (Pass 0) that processes the raw `AnalyzedRepo` objects (no README, just metadata) before the existing passes run.

## Goals / Non-Goals

**Goals:**
- Give the consolidation prompt visibility on per-category repo count and topic signals.
- Keep the new pass cheap: no READMEs, no per-repo round-trips — one prompt with all metadata.
- Minimal signature change: `consolidateCategories` gains one optional parameter; existing call-sites that don't pass it fall back gracefully.
- The distribution summary is fire-and-forget: if Pass 0 fails, consolidation continues unchanged.

**Non-Goals:**
- Changing the output shape of `consolidateCategories` or `ConsolidationResult`.
- Exposing the distribution summary in the review UI or JSON output.
- Re-running per-repo analysis.

## Decisions

### D1 — New pass before language-qualifier deduplication (Pass 0), not after

**Decision:** Insert the distribution summary pass before Pass 1.

**Rationale:** The language-qualifier pass already collapses synonyms, so by the time Pass 2 sees the names the distribution signal is stale (multiple names have been merged). Running Pass 0 on the raw proposed names keeps counts accurate and the summary directly comparable to what Pass 2 merges.

**Alternative considered:** Attach distribution data to the Pass 2 prompt directly using `analyzedRepos` without a separate AI step. Rejected because the raw list of repos-per-category can be hundreds of lines; an AI-written compact summary is shorter and fits token budgets.

### D2 — Distribution summary is a plain text block injected into the existing consolidation prompt

**Decision:** `buildConsolidationPrompt` accepts an optional `distributionContext: string` parameter. When present it is appended as a `DISTRIBUTION CONTEXT` section before the `NOW PROCESS THIS INPUT` line.

**Rationale:** Avoids a parallel prompt variant; keeps the consolidation prompt as the single source of truth for merge rules.

**Alternative considered:** Separate "distribution-aware" prompt function. Rejected — would duplicate all the canonical-name rules.

### D3 — Pass 0 prompt asks for a compact summary, not a merge decision

**Decision:** `buildDistributionSummaryPrompt` asks the AI to return a JSON object mapping each category name to `{ count: number, topics: string[] }`. The coordinator formats this into a human-readable block before injecting it.

**Rationale:** JSON is machine-parseable; we can fall back cleanly if it is malformed. A human-readable reformatting step in the coordinator means the consolidation prompt stays readable.

### D4 — `consolidateCategories` signature change is backward-compatible

**Decision:** Add `analyzedRepos?: AnalyzedRepo[]` as an optional last parameter (after `parent`).

**Rationale:** There are three call-sites; making it optional lets them be updated incrementally without a flag day. The new parameter comes after the existing `parent` trace parameter.

## Risks / Trade-offs

- **Extra LLM call latency** — Pass 0 adds one prompt per consolidation run. Mitigated by: it runs only when `analyzedRepos` is provided; it uses a compact prompt with no READMEs; failure is silently swallowed.
- **Token cost** — Large repo sets (hundreds of repos) could produce a large Pass 0 prompt. Mitigated by sending only `name`, `description`, `language`, and `topics` (no readme), and capping the injected summary to the most distinctive topics per category.
- **Summary accuracy** — Pass 0 is itself an AI output, so the distribution context it produces could be subtly wrong. This is acceptable because it is advisory context for Pass 2, not a hard constraint.

## Migration Plan

1. Add `buildDistributionSummaryPrompt` to `prompts.ts`; update `buildConsolidationPrompt` to accept optional `distributionContext`.
2. Add Pass 0 logic to `consolidationCoordinator.ts`; update `consolidateCategories` signature.
3. Update `review.ts`, `analysis.ts`, `cli/modes.ts` to pass `analyzedRepos` through.
4. Update `consolidator.test.ts` to cover Pass 0 behavior and fallback.

No data migrations or deploy coordination required — all changes are local to the Node process.

## Open Questions

- Should the distribution context include repo names (for human traceability in Langfuse traces), or only aggregate counts + topics? Leaning toward names omitted to keep token usage low and avoid misleading the consolidation AI with individual repo names.
