# `evals/` — retrieval eval fixtures

Committed, frozen test data for the retrieval eval harness. `bun run evals` searches this data and grades the result — see the [Retrieval Evals](../README.md#-retrieval-evals) section of the root README for the why and the metrics.

Everything here runs **offline**: no GitHub token, no AI backend, no network. The data is committed precisely so the score is reproducible (and CI-gateable).

## Files

| File | What it is | Who writes it |
| --- | --- | --- |
| `repos.json` | Curated list of `owner/name` public repos — the input to the corpus builder. | Human (edit to add/remove repos) |
| `corpus.json` | Frozen analyzer output for each repo (`owner`, `name`, `topics`, `category`, `killerFeature`, `description`, `isArchived`). The **haystack** search digs through. | Generated by `bun run evals:build-corpus` |
| `queries.json` | Hand-authored questions, each with one or more ground-truth repo URLs. The **test**. | Human |
| `baseline.json` | The scorecard today's keyword retriever achieves over this corpus + queryset. The **floor** a smarter retriever (#44) must beat. | Generated by `bun run evals` |

## Add or change a golden query (single PR, no code)

1. Edit `queries.json`. Each entry:
   ```json
   {
     "question": "rust command-line tool that searches file contents",
     "expected": ["github.com/BurntSushi/ripgrep"],
     "style": "exact-recall"
   }
   ```
   - `expected` is one or more repo URLs (`github.com/<owner>/<name>`). **Every URL must already exist in `corpus.json`** — the harness fails fast and names any dangling reference.
   - `style` (optional, documentation only): `exact-recall` · `categorical` · `property-based` · `logical` · `health-check`.
2. Run `bun run evals` to refresh `baseline.json`.
3. Commit both files.

## Refresh the corpus (needs secrets)

To re-analyze repos or add new ones:

1. Edit `repos.json`.
2. `bun run evals:build-corpus` — requires `GITHUB_TOKEN` and an AI backend (`--backend ollama` or OpenAI). Fetches public metadata + README per repo and runs the real analyzer, rewriting `corpus.json`.
3. `bun run evals` to refresh `baseline.json`.
4. Commit `repos.json`, `corpus.json`, and `baseline.json` together.

> Refreshing the corpus changes the haystack, so existing query scores can shift — always re-commit `baseline.json` in the same PR. The CI `evals --check` gate fails if the committed baseline no longer reproduces.

## Coverage notes

- The corpus is curated **public** repos so query authors share a stable, recognizable haystack — it is not anyone's personal stars.
- Query styles span exact-recall, categorical, property-based, logical (AND/OR/negation), and health-check, across lengths from 1–2 word terms to long natural-language sentences.
- Health-check coverage is currently thin: only one corpus repo is archived. Add more archived repos to `repos.json` to strengthen it.
